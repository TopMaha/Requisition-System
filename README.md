## วิธีติดตั้ง (ครั้งแรก)

### ขั้นที่ 1 — ติดตั้ง Node.js และ Wrangler
```
npm install -g wrangler
```

### ขั้นที่ 2 — รัน deploy.bat
ดับเบิลคลิก `deploy.bat` ทำตามขั้นตอน:
1. Login Cloudflare
2. สร้าง D1 database → copy `database_id`
3. วาง `database_id` ใน `wrangler.toml`
4. Deploy Worker

### ขั้นที่ 3 — ตั้งค่าใน index.html
1. เปิด `index.html` ในเบราว์เซอร์
2. กดปุ่ม ⚙️ มุมบนขวา
3. ใส่ Worker URL (เช่น `https://requisition-system.xxx.workers.dev`)
4. ใส่ Admin Password (default: `admin1234`)
5. กดบันทึก

## แยกข้อมูลตาม VSM (VSM3 / VSM4)

ข้อมูลทั้งหมด (อุปกรณ์, Stock, ใบเบิก, เครื่องจักร, รายชื่อเพิ่มเติม) แยกตาม VSM —
**ข้อมูลที่มีอยู่ก่อนหน้านี้ทั้งหมดเป็นของ VSM4**, VSM3 เริ่มจากว่าง

- **ล็อก VSM ทันทีที่เข้าสู่ระบบ** — ไม่มีปุ่มสลับ ต้องออกจากระบบแล้วเข้าใหม่
  - พนักงาน: กรอกรหัส → ระบบดูรายชื่อใน **PSIF** ว่าสังกัด VSM ไหน แล้วเข้า VSM นั้นเลย
  - Admin: เลือก VSM3 / VSM4 ก่อนใส่รหัสผ่าน
- หัวจอแสดงป้าย VSM และ **VSM3 ใช้ธีมสีเขียวอมฟ้า** (VSM4 สีน้ำเงินเดิม) — ดูปุ๊บรู้ว่าอยู่ VSM ไหน
- **รายชื่อพนักงานอ้างอิงจากโปรเจกต์ PSIF** (binding `PSIF_DB` → `psif-db`, อ่านอย่างเดียว)
  - คนที่ PSIF ระบุว่าอยู่ VSM3/VSM4 และยัง active → เข้าได้ทันที ไม่ต้องเพิ่มชื่อ
  - คนนอก VSM3/VSM4 (เช่น ช่างซ่อมบำรุง) → Admin เพิ่มที่ **👥 ฐานข้อมูลพนักงาน** ใน VSM ที่ต้องการ
  - คนที่ PSIF ปิดใช้งาน (ลาออก) → เข้าไม่ได้
- รหัสอุปกรณ์รันแยกกัน: VSM4 = `I-0001…` (เดิม), VSM3 = `V3-0001…` — รหัสห้ามซ้ำทุก VSM
- ใบเบิกถูกบันทึกเข้า VSM ของผู้เบิกตามรายชื่อ PSIF (ฝั่ง Worker ตรวจเอง)
- (ถ้าต้องการ) ตั้งรหัสผ่าน Admin แยกราย VSM: `wrangler secret put ADMIN_PASSWORD_VSM3` —
  รหัสนี้เข้าได้เฉพาะ VSM3, ส่วน `ADMIN_PASSWORD` เดิมยังเข้าได้ทุก VSM

## วิธีใช้งาน

### สำหรับพนักงาน (เบิกของ) — สแกน QR Code บน Part
1. เข้าสู่ระบบด้วยรหัสพนักงาน (ระบบพาเข้า VSM ของตัวเองอัตโนมัติ)
2. แท็บ **📷 เบิกของ** → แตะ **สแกน QR Code** แล้วเล็งกล้องไปที่ป้ายบน Part — ระบบอ่านรหัสให้อัตโนมัติ **ไม่ต้องกดถ่าย**
   - ไม่มีป้าย / สแกนไม่ได้ → **พิมพ์รหัส Item Part** แทนได้ (ถ้าพิมพ์ไม่ตรง ระบบเสนอรายการใกล้เคียงให้เลือก)
3. ระบบแสดง **รูปชิ้นงาน ชื่อ รหัส และ Stock คงเหลือ** — ดูให้ตรงกับของจริง
4. กรอกแค่ 3 อย่าง: **จำนวน**, **นำไปใช้เครื่องไหน**, **จุดประสงค์**
5. กด **"✅ ยืนยัน ส่งคำขอเบิกให้ Admin"** → ติดตามสถานะที่แท็บ **📋 ประวัติ**

> แท็บ **📦 คลังสินค้า** และการ์ด **📥 รับของเข้า** ของ Admin มีปุ่ม **📷 สแกน** เช่นกัน — สแกนป้ายเพื่อดู Stock / รับของเข้าได้เลย

### สำหรับ Admin (ตรวจสอบ + อนุมัติ)
1. แท็บ **🔧 Admin** → การ์ด **📥 คำขอเบิกรอตรวจสอบ** (ตัวเลขแดงบนแท็บ = จำนวนที่รอ)
2. กด **🔍 ตรวจสอบ & อนุมัติ** → เห็นรูป Item และรายการที่พนักงานสแกนมาแล้ว — แก้จำนวน / เพิ่ม Item ได้
3. เลือกผล: **อนุมัติ + จ่ายของ (ตัด Stock ทันที)** / **อนุมัติ (จ่ายทีหลัง)** / **ไม่อนุมัติ**
4. ดูการ์ด **📊 ยอดเบิก & คาดการณ์ของหมด** — เบิกไปเท่าไร และ Item ไหนจะหมดในกี่วัน

> ใบเบิกเก่าที่แนบรูปถ่าย ยังเปิดดูรูป ระบุ Item (**🔍 ตรวจสอบ & ใส่ Item**) และอนุมัติได้เหมือนเดิม

### พิมพ์ป้าย QR Code ติด Part (Admin)
1. แท็บ **🔧 Admin** → การ์ด **🏷️ ป้าย QR Code ติด Part** → ค้นหา / เลือกหมวด / ติ๊กเลือก Item (ตัวอย่าง: พิมพ์รหัสเดียวเพื่อพิมพ์ป้ายที่ชำรุดใหม่)
2. กด **📥 Export Excel** — ได้ไฟล์ `QR-Labels-<VSM>-<วันที่>.xlsx`
   - ชีต **ป้าย QR** — ป้ายสำหรับพิมพ์: A4, 15 ป้ายต่อหน้า (QR + รหัส + ชื่อ) **สั่งพิมพ์ที่ขนาด 100%** แล้วตัดตามเส้นประ
   - ชีต **รายการ** — 1 แถวต่อ 1 Item ใช้ตรวจเช็กตอนติดป้าย / กรองข้อมูล
3. ติดป้ายที่ Part / กล่อง / ชั้นวาง

ใน QR มีแค่ **รหัส Item Part** (เช่น `I-0012`) จึงเป็น QR ขนาดเล็กที่สแกนง่าย และป้ายเดิมยังสแกนได้แม้แก้ชื่อหรือรูปของ Item
รูปที่พนักงานเห็นหลังสแกนคือรูปของ Item ในระบบ — การ์ดนี้แสดงจำนวน Item ที่ **ยังไม่มีรูป** ให้เติมได้ที่ **📋 จัดการอุปกรณ์**

> สแกนต้องเปิดเว็บผ่าน https · Android ใช้ตัวอ่าน QR ในเบราว์เซอร์ ส่วน iPhone / คอมพิวเตอร์ และการ Export Excel โหลดไลบรารีจาก CDN (jsDelivr) ตอนใช้งานครั้งแรก จึงต้องต่ออินเทอร์เน็ต

## ทำไมเปลี่ยนมาใช้ QR Code

ระบบรุ่นแรกใช้ AI จับคู่รูปกับ Item (รูปไม่ชัด ต้องใช้รูปจำนวนมากสอน AI) รุ่นถัดมาให้ Admin ดูรูปแล้วระบุ Item เอง (Admin ต้องไล่หา Item ทุกใบ และรูปกินพื้นที่) จึงเปลี่ยนเป็นสแกน QR:
- รหัสใน QR ตรงกับ Item ทันที → **ไม่ต้องเดา / ไม่ต้องหา Item**
- **ไม่เก็บรูปการเบิกแต่ละครั้ง** → ลดพื้นที่จัดเก็บ (รูปของใบเบิกเก่ายังอยู่เหมือนเดิม)
- Admin ยังตรวจทุกใบก่อนจ่าย และเห็นยอดเบิก + คาดการณ์ของหมด → **ไม่ขาดแคลน**

> Endpoint AI เดิม (`/api/match` ฯลฯ) ยังอยู่ใน `worker.js` แต่หน้าเว็บไม่เรียกใช้แล้ว
>
> หน้าเว็บที่เปิดค้างจากรุ่นถ่ายรูป ถ้าส่งใบเบิกแบบแนบรูป จะได้รับข้อความให้ปิดแล้วเปิดหน้าเว็บใหม่ (ระบบไม่รับรูปแล้ว)

## Database Schema

- `categories` — หมวดหมู่อุปกรณ์
- `items` — รายการอุปกรณ์/อะไหล่
- `requisitions` — ใบเบิก (ผู้เบิก, เครื่อง, จุดประสงค์, จำนวนที่ขอ, สถานะ)
- `requisition_photos` — รูปของใบเบิกเก่าเท่านั้น (ระบบใหม่ไม่เก็บรูป)
- `requisition_items` — Item Part ของใบเบิก: จาก QR ที่สแกน และ Admin แก้ / เพิ่มได้ (1 ใบเบิกมีได้หลาย Item)
- `stock_movements` — ประวัติการเคลื่อนไหว Stock (ใช้คำนวณยอดเบิก)
- คอลัมน์ `vsm` (`VSM3` | `VSM4`, ค่าเริ่มต้น `VSM4`) ใน `items`, `requisitions`, `employees`, `machines`, `scan_reports`, `match_feedback`

ตาราง/คอลัมน์ใหม่ถูกสร้างอัตโนมัติเมื่อ Worker ทำงานครั้งแรก (ไม่ต้องรัน SQL เอง)

## เปลี่ยน Admin Password

แก้ในไฟล์ `wrangler.toml`:
```toml
[vars]
ADMIN_PASSWORD = "รหัสใหม่"
```
แล้วรัน `wrangler deploy` อีกครั้ง
